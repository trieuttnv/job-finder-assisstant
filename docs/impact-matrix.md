# Impact matrix

How each design decision affects the outcomes the evaluation measures. Each row gives the mechanism, the signal to watch and the eval metric that catches a regression. The tensions, where two decisions pull against each other, are resolved in the [README](../README.md#cross-task-design).

| # | Decision | Affects | Mechanism | Signal | Eval metric that catches it |
|---|---|---|---|---|---|
| D1 | One typed Entry per bullet, linked to its role ([ADR 0001](adr/0001-typed-entries-with-verbatim-quotes.md)) | Citation precision, answer correctness | Citations point at one line; role header brings employer and dates. Bullets too short to match a question lower recall | Gold ids missing from retrieval | Recall@k, citation correctness |
| D2 | Readable stable ids + ingest diff | Eval stability | Re-ingest keeps ids, so Gold Labels keep resolving; the diff names any id that moved | Ids removed or changed at ingest | Gold ids that no longer resolve (eval refuses to run) |
| D3 | Committed Snapshots, no live fetch | Reproducibility, freshness | Every run reads the same text; the knowledge base is stale until re-snapshotted | Snapshot date in `sources.yaml` | Quote provenance (Hard Line) |
| D4 | Quote must appear word for word in its Snapshot | No fabrication in the knowledge base | An Entry can't say more than its Source; a mistyped Quote stops ingest | Ingest failures | Quote provenance (Hard Line) |
| D5 | BM25 top-6, typed filters, role and Conflict expansion ([ADR 0002](adr/0002-bm25-and-typed-filters-over-embeddings.md)) | Recall, context size, latency, cost | Lexical match misses paraphrase; expansion adds Entries and tokens; a larger context invites cross-Entry invention | Retrieved-set size, tokens per question | Recall@k per category, mean cost, hallucination rate |
| D6 | Input Guardrail score floor | Refusals, cost | Floor too high refuses answerable paraphrases; too low sends unanswerable questions to their one model call | Share of questions stopped before the model | Over-refusal, refusal correctness, mean cost |
| D7 | Fixed pipeline, one model call ([ADR 0003](adr/0003-fixed-pipeline-over-agent-and-no-llm-baseline.md)) | Latency, cost, multi-source answers | Predictable cost and p95; a single retrieval pass can miss context for multi-part questions | Multi-source failures tagged *retrieval miss* | Answer correctness on multi-source, p95, mean cost |
| D8 | Claims JSON with Entry ids | Parse failures, citation correctness | A model that breaks the schema ends in the plain error; a claim without ids is dropped | Parse-failure count in traces | Over-refusal (a parse failure is a fallback), citation correctness |
| D9 | Output Guardrail rules: ids, numbers, names ([ADR 0004](adr/0004-output-guardrail-is-code.md)) | Hallucination, answer correctness | Stops invented numbers and names; drops honest paraphrase; can't see recombination of real words | Claims dropped per answer | Hallucination rate, guardrail drop rate, answer correctness |
| D10 | Drop ratio 0.5 withholds the answer | Over-refusal, safety | Lower ratio withholds more partial answers; higher shows answers with gaps | Answers withheld as unverified | Over-refusal, answer correctness |
| D11 | Conflicts rendered by code | Conflict correctness, noise | Both sides always cited when it applies; may add an off-topic notice | Conflict notices on non-Conflict questions | Conflict questions (multi-source), answer correctness |
| D12 | No injection pattern list | Adversarial safety | Injected instructions reach the model; only the Output Guardrail stands between them and the Interviewer | Adversarial failures | Hallucination rate on adversarial (Hard Line) |
| D13 | Two providers by config ([ADR 0005](adr/0005-switchable-model-adapters-anthropic-and-deepseek.md)) | Schema compliance, cost, p95 | Providers differ in following the claim schema and in price and speed | Parse failures and drop rate per provider | Every metric, per provider row |
| D14 | Fixed-message fallback, timeout without retry | Availability, over-refusal | A slow or failing provider becomes "can't answer right now" | Fallbacks of mode `unavailable` | Over-refusal (counts against the run), p95 |
| D15 | Code-only judge with term lists ([ADR 0006](adr/0006-code-is-the-only-judge.md)) | Metric trust | Recomputable; misses correct paraphrase; can mirror the guardrail's own rules | *Label too strict* errors | Answer correctness (false misses), hallucination rate (blind spots) |
| D16 | 30 questions, dev / held-out | Overfitting | Tuning only on dev keeps held-out honest; 10 held-out questions give wide error bars | Dev vs held-out gap | Every metric on held-out |
| D17 | CLI, no history, no streaming | Answer completeness | Follow-ups must restate context; the whole answer is checked before display | — | No downstream effect on metrics: every eval question is single-turn by design |
| D18 | Email redacted only | Privacy | The email never reaches a model or the repository | — | No downstream effect on metrics: no question needs the email |
| D19 | JSONL traces | Measurement | Cost and p95 are computed from the same records the CLI writes | Missing trace fields | p95, mean cost (eval reads traces) |
