# Transactional Outbox Prototype

## Design

- One 12-partition `order-created.v1` topic. The `order-writer` role commits an
  order row and an `outbox` row in **one** `pgx` transaction and constructs **no**
  `kafka.Writer` — the structural absence is the proof there is no dual write.
- `relay` polls `outbox WHERE published_at IS NULL ORDER BY id`, publishes to
  Kafka keyed by `aggregate_id` (per-order ordering), then marks the row. Three
  interchangeable claim strategies (`none | skip-locked | lease`) share one
  signature so the publish path is written once.
- `verifier` consumes the topic (group `outbox-verifier`, manual commit after the
  DB write) and appends every delivery to `published_events`. It records
  duplicates, it does not swallow them.
- `ballast` grows `outbox` to 500K already-published rows in one statement so the
  index experiment does not take hours.
- `reconciler` reads the tables and writes `outbox_report.md`.
- Two relays run concurrently on purpose, with the broken `none` mode as the
  default, so duplicate publishes are observed rather than argued about.

### Column decisions

- **`outbox.id BIGSERIAL`** gives a cheap FIFO `ORDER BY id` and a narrow index
  key. Hazard: sequence values are handed out *before* commit, so a lower `id`
  can become visible *after* a higher one. A relay must therefore never track a
  high-water-mark cursor (`WHERE id > last_seen`) — that silently skips events.
  The poll predicate is always `published_at IS NULL`. This prototype dodges the
  bug by construction.
- **`event_id UUID UNIQUE`** is generated by the writer inside the transaction,
  so every republish of a row carries the same value. That is what makes
  at-least-once survivable for a downstream idempotent receiver.
- **`payload JSONB`** carries the fully-formed event including `committed_at`, so
  the relay never re-reads `orders` and the verifier computes latency without a
  join.
- **`published_at` nullable** rather than a `published BOOLEAN`: one column is
  both the poll predicate and the sweep cursor
  (`DELETE WHERE published_at < now() - interval`).
- **`claimed_by` / `claimed_at`** exist only for `lease` mode — the visible cost
  of that strategy (two writes per row, plus row width paid by every mode).
- **`orders.phase`** is stamped by the writer and copied into the payload, so the
  reconciler splits duplicates burst-vs-steady with a plain `GROUP BY`.
- **Partial index `(id) WHERE published_at IS NULL`** is the crux: its size is
  O(backlog), not O(table). `make index-plain` swaps in a plain
  `(published_at, id)` index to measure the difference.
- **`published_events` has NO unique on `event_id`** — deliberately. Relay
  duplicates must be recorded. `UNIQUE (kafka_partition, kafka_offset)` gives the
  verifier its own idempotency against Kafka redelivery without hiding those
  duplicates. Two different problems, kept separate by the schema.

## Runtime experiment

1. `make up` (one relay, `claim=none`, `cleanup=none`), then `make write`.
   Expect publish p99 well under 2s at 50/sec, poll p99 sub-millisecond, backlog
   near zero, **zero duplicates** — `none` is not wrong with a single relay.
2. `make up-2relays`, `make write`. Expect `outbox_duplicate_events_total` to
   climb immediately; the report shows the same `outbox_row_id` published by both
   relays; the duplicate rate is higher in the burst phase.
3. `make mode-skip-locked`, rerun. Concurrency duplicates → 0, per-relay counters
   split the work. Then `make relay-failpoint`: a crash between produce and mark
   reintroduces duplicates — still at-least-once.
4. `make mode-lease`, rerun. No long-held transaction across the broker
   round-trip, at the cost of a second write per row and a duplicate window equal
   to the lease TTL after a crash.
5. `make ballast`, then `make poll-explain` and read poll p99 under the partial
   index.
6. `make index-plain`, rerun load, measure again — the second `index_kind` series
   on the same panel is the central claim. `make index-partial` to restore.
7. `make cleanup-sweep`. Expect `published_undeleted_rows` and table size to fall
   and poll p99 to return to baseline.
8. `make report` + `make verify`. Final assertions: `lost = 0` in every mode,
   `p99 publish latency < 2s`, `extra_publishes > 0` under `none` and `= 0` under
   `skip-locked` absent a crash.
