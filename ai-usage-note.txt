AI usage note

Tools
- Claude Code with Claude Opus 5.5 for the design, code, tests and evaluation work.
- Claude Haiku 4.5 is the model the assistant itself calls in the committed eval runs.
- Skills from https://github.com/mattpocock/skills, plus "grilling-exercise", a skill I wrote for
  this project that extends grilling-to-docs.

How I used it
1. Design. The grilling-exercise skill interviewed me and I answered its questions one by one.
   My answers became the README (the system design) and the ADRs.
2. Research. During the system design review I used the research skill for:
   - chunking;
   - how to add a new source without changing the design. The skill didn't find the approach I
     wanted, so I proposed the pipeline and asked it to research that: Discover -> Fetch ->
     Snapshot -> Extract/Map -> Normalise -> Validate -> Provenance -> Diff -> Review/Quarantine
     -> Publish. The result is docs/adr/0009-ten-stage-ingestion-pipeline-with-source-connectors.md.
3. Tickets. When the design was finished, the to-ticket skill split it into 12 tickets.
4. Build. Each ticket was implemented with the implement skill, test-first, and then checked with
   the code-review skill. What the model generated for each ticket is logged in docs/ai-usage.md.
5. Evaluation. I used the eval-debug skill to analyse the failing eval items: prove each root cause
   with an experiment, fix only on dev, and measure held-out once per change. I chose every fix;
   Claude wrote the prompt versions answer-v2 to answer-v4, the retrieval type words, the
   replacement held-out questions q31 and q32, and the tests. The analysis is failure_analysis.md.
